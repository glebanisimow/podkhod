# Обновления Android из GitHub

После push в `main` workflow `build-apk` запускает тесты, собирает APK с тем же ключом подписи
и публикует его в [Android-релизе](https://github.com/glebanisimow/podkhod/releases/tag/android).
Обновление становится доступно после успешного завершения сборки, а не сразу после push.
Теги `v*` по-прежнему получают отдельные релизы; они не меняют канал обновлений из `main`.

## Первая установка

Один раз установите [podkhod-latest.apk](https://github.com/glebanisimow/podkhod/releases/download/android/podkhod-latest.apk)
поверх существующего приложения. Удалять прежнюю версию не нужно. Это добавит кнопку обновления.

Дальше: **Настройки → Прочее → Обновление приложения → Проверить обновления → Обновить**.
Приложение скачает APK и откроет системное окно установки. Android попросит подтвердить обновление.
В первый раз также нужно разрешить «Подходу» установку приложений из этого источника; после возврата
из настроек установка продолжится. Если отменили установку, нажмите «Установить обновление» снова.

Тренировки и настройки сохраняются. Установка откладывается, пока есть незавершённая тренировка.
Проверка запускается только по кнопке: без интернета приложение продолжает работать как раньше.
Обновления предназначены для основной версии `app.podkhod`; debug устанавливается отдельно.
После закрытия процесса во время загрузки нужно заново нажать проверку и загрузку.

## Публикация

Нужные GitHub Actions secrets уже используются существующей сборкой:
`PODKHOD_KEYSTORE_BASE64`, `PODKHOD_KEYSTORE_PASSWORD`, `PODKHOD_KEY_ALIAS`, `PODKHOD_KEY_PASSWORD`.
Ключ должен совпадать с подписью установленного приложения. GitHub-токен в APK не попадает:
репозиторий и APK доступны публично.

В релизе с тегом `android`:

- `podkhod-<versionCode>-<runId>-<attempt>.apk` — файл конкретной сборки;
- `podkhod-latest.apk` — ссылка для первой ручной установки;
- `update.json` — номер и имя версии, пакет, минимальный Android, размер, SHA-256 и ссылка на APK.

`tools/build_update_manifest.py` читает сведения из готового APK через `aapt2`. Workflow сначала
загружает APK, затем обновляет `update.json`. Предыдущие файлы APK сохраняются, чтобы уже начатая
проверка могла скачать свою версию. Пока `update.json` заменяется, возможен короткий ответ 404 —
приложение предложит повторить проверку.

Сборки `main` публикуются последовательно; перед публикацией проверяется, что коммит остаётся
текущим `main`. Неудачная сборка не заменяет последнее рабочее обновление.
`versionCode` берётся из APK и сравнивается с установленной сборкой, даже если `versionName` одинаковый.

Приложение ограничивает размер загрузки, проверяет SHA-256, имя пакета, номер и имя версии,
а также совпадение сертификатов подписи с установленной версией. Установку выполняет Android.
APK хранится в отдельном подкаталоге кэша; FileProvider открывает только этот подкаталог.

## Проверки

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
```

Тесты обновления проверяют сравнение сборок, адреса загрузки и метаданные, повтор после ошибки сети,
отложенную установку при тренировке, повтор установки после отмены и отказ при повреждённом APK.

На устройстве: установить первую сборку с кнопкой, дождаться следующей успешной публикации,
проверить обновление, разрешить установку из «Подхода» и подтвердить обновление. После запуска
проверить номер сборки и сохранность истории тренировок.
